# CoalGuard Reproducible Demo Walkthrough

This walkthrough helps a reviewer follow the application and understand what each result means. The live simulator and configured test cases use deterministic synthetic models. The published-data replay is a separate evidence feature; neither one is an industrial field trial.

## Start the application

From the project folder:

```bash
npm install
npm run dev -- --port 3002
```

Open [http://localhost:3002](http://localhost:3002). Use the project README for the full setup, test, lint, and production-build commands.

## 1. Establish project scope

Open the Dashboard and explain the project as an academic decision-support prototype for examining explainable coal-fire risk signals. It demonstrates a Mamdani Fuzzy Inference System and an offline PSO calibration process. It does not connect to physical sensors or control equipment.

## 2. Show a process simulation

Open **Simulation**, choose one of the five operating profiles, then select a scenario that is available for that profile. Adjust one or more telemetry controls and observe how the virtual process readings, risk trajectory, risk stage, and explanation respond. The values are generated by CoalGuard's local process and sensor models; they are not live industrial telemetry.

Use a self-heating case to illustrate a thermal and gas trend, or a mechanical-friction case to illustrate why vibration and motor-current evidence can point to a different cause. Describe the behavior actually shown on screen rather than promising a specific number or risk stage.

## 3. Trace a decision

Open **Explain Risk** after selecting or running a case. Follow the current inputs into their fuzzy membership grades, inspect the active rules and their firing strengths, then show how the aggregated fuzzy output is defuzzified into a risk score. Explain that a rule firing strength is not a probability and that the suggested response is simulated guidance, not an equipment command.

## 4. Run a configured test case

Open **Test Cases**, select a case, and review its environment, configured inputs, expected behavior, and evaluation checks. Run the case and inspect the resulting trajectory and checks. These cases demonstrate repeatable behavior against project-defined synthetic examples; they are not independent field validation.

## 5. Explain the PSO workbench accurately

In the PSO Calibration Workbench, run the seeded calibration and inspect its convergence trace and parameter-shift table. The current button uses 24 particles, 40 iterations, and seed 42. PSO searches numerical membership-function breakpoints and rule weights against six labelled synthetic examples. It is an offline calibration run, not continuous self-learning and not a direct ranking of sensor importance.

Do not claim that PSO improves field performance just because the objective loss falls during calibration. On CoalGuard's separate published-data replay, Basic Mamdani and PSO-tuned Mamdani had the same episode alert counts; their median warning leads were 100 and 108 hours respectively. The CO-threshold comparator had a 232-hour median lead under CoalGuard's stated policy. These small-sample results do not show PSO superiority.

## 6. Inspect the evidence replay

Open **Evidence** and distinguish the measured source records from CoalGuard's calculated outputs. The underground-mine replay covers 18 episodes (3 confirmed fires and 15 event-free periods). It uses the available temperature, CO, and derived temperature-trend inputs; unavailable channels are not filled with invented measurements. Explain that 232 hours is CoalGuard's recomputation under its 24-hour persistence policy, while the source paper reports 276 hours under a different convention.

The replay is exploratory and does not validate the five simulated profiles or establish future detection and false-alarm rates. See [Published Replay Notes](./REAL_DATA_REPLAY.md) and [Evidence Notes](./EVIDENCE_NOTES.md) for the data, policy, citations, and caveats.

## Suggested closing statement

“CoalGuard demonstrates how fuzzy rules can combine uncertain indicators and expose an interpretable risk result, while PSO provides a repeatable way to calibrate selected numerical parameters. Our simulator is synthetic, and our small published-data replay is exploratory. The next research need is broader, site-matched labelled data and an independent evaluation protocol.”
